# GenieTerm 1.4

When a server on an SSH host prints its `localhost` URL, GenieTerm offers to open it on this computer. One click forwards the port and opens the page, with its path and token intact.

## Open remote servers here

- **It finds the URL for you.** TensorBoard, Jupyter, Gradio, Vite, `python -m http.server` and anything else that prints `http://localhost:…`, `127.0.0.1`, `0.0.0.0` or `[::1]` in an SSH terminal gets a small offer under the terminal: **Open in Browser**.
- **The whole URL comes along.** The path, query and token are kept, so a Jupyter link opens signed in. If the port is taken on this computer, GenieTerm picks a free one and opens that instead.
- **Only for servers.** The offer appears when the command that printed the URL is still running a moment later, so `cat`, `grep` and log files that mention localhost stay quiet. It goes away when the server stops.
- **Cmd-click does the right thing.** In an SSH terminal, Cmd-click (Ctrl-click on Linux and Windows) on a localhost link now opens the remote machine's port through a forward, not the same port on this computer.
- **Already forwarded?** If Host already forwards that port, the offer just opens it.
- **Turn it off** under Settings → General → Sessions & connections, or per host with `term:forwardoffer` in `connections.json`. Forwards still show in Host, where you can stop them.

## Install and update

- **macOS** (Apple Silicon and Intel): the app is not notarized. After the first launch attempt, allow it under System Settings → Privacy & Security → "Open Anyway". GenieTerm 0.4.83 and later update in the app.
- **Linux:** download the AppImage or .deb for your architecture from this release. AppImage installs update themselves. A .deb install shows **Update Available** and points you to the new package.
- **Windows x64** remains an unsigned preview published on prerelease tags.
